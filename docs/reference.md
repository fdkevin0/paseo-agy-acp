# Reference

For installation and your first request, start with the [installation guide](../README.md#install). For source layout and verification, see [development](development.md).

## Launch and data directories

Plugin `agy-acp` registers provider `agy`. The default command is `agy acp`. Paseo resolves the executable, argument prefix and launch environment; session environment overrides are applied on top. Session MCP servers are translated into ACP stdio, HTTP or SSE configurations; non-empty session system prompts are forwarded via `_meta.antigravity.systemPrompt.append`.

| Setting                            | Behavior                                                                                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Command and argument overrides     | Use Paseo's provider launch configuration to choose an executable and argument prefix.                                                           |
| `HOME` / `USERPROFILE`             | Session environment takes precedence over launch environment (`HOME`, then `USERPROFILE`, ignoring empty strings), then the host home directory. |
| `--gemini-dir`, `--gemini_dir`     | Override the Gemini directory; relative paths resolve against the realpath of the session's `cwd`. Default is `$HOME/.gemini`.                   |
| `--app-data-dir`, `--app_data_dir` | Override the application directory; relative paths resolve under the resolved Gemini directory. Default is `antigravity-cli`.                    |

The resolved native directory is used for temporary artifact cleanup, Brain tracking and quota account identity. Flag-like argument values (starting with `-` without `=`) are ignored so misplaced flags cannot become directory paths. Other vendor directory overrides are not interpreted. See [subscription quota](#subscription-quota) for agy print-mode restrictions on directory flags.

### Availability and catalog discovery

Provider status runs the executable with `--version`, with a five-second timeout, requires a parseable version of at least 1.5.10 (pre-release `1.5.10-*` builds are rejected), coalesces concurrent probes, and caches successful checks for 60 seconds per resolved launch-and-binary key (bounded to 100 entries) so replacing, downgrading or removing the executable invalidates cached availability immediately. Every ACP runtime, including a replacement, must also report a supported `agentInfo.version` during `initialize`. Catalog identity hashes the command, arguments, sorted environment, and resolved executable fingerprint (`realpath`, device, inode, size, and `mtimeNs`, resolving case-insensitive `PATH`/`Path` with outer-quote stripping, Windows `PATHEXT`/`stat().isFile()`, and default install-path fallbacks `~/.local/bin/agy` or `%LOCALAPPDATA%\agy\bin\agy.exe` / `~/AppData/Local/agy/bin/agy.exe` for bare `agy` or Windows case-insensitive `agy` / `agy.exe`, ignoring `force` per Paseo's identity contract and falling back to the base key if the executable cannot be resolved) using SHA-256; environment values are not included in plain-text cache keys. Within a connection, cwd-independent launches lazily start and reuse a single idle-reaped (5-minute) shared `agy acp` control runtime across `catalog` and `sessions` probes (serializing concurrent `catalog` probes so per-probe `models` and `tier` metadata never cross-contaminate, retiring and restarting the control process on executable fingerprint changes, unexpected exit, or `session/close` failure); cwd-dependent launches (relative executable or relative `--gemini-dir` path) fall back to one-shot runtimes closed immediately after each probe. For non-`full-access`, cwd-independent launches, the connection also maintains a bounded, idle-reaped (5-minute, 4-slot LRU) `StandbyRuntimePool` keyed by the SHA-256 hash of command, arguments, resolved environment (case-insensitively deduplicated on Windows), and resolved executable fingerprint: successful `catalog` or `sessions` probes, persisted session opens, first prompts on new sessions, and non-`full-access` standby relaunches warm one standby runtime in the background (`initialize` plus `session/list` when advertised; `--dangerously-skip-permissions` launches are refused inside `warm()` as well as `recycle()`) for exclusive 1:1 checkout by interactive sessions and relaunches, proactively retiring stale-binary slots when the executable changes while preserving full process isolation per active session and opting out on cwd-dependent launches. Concurrent catalog requests for the same resolved spawn directory share an in-flight probe (bounded to 100 directories per connection); once a probe settles, the entry is cleared so subsequent refreshes re-probe `agy acp`, and failed probes do not replace remembered usage launches. When `cwd` is missing, `catalog` and `sessions` probes fall back to the resolved `HOME` directory only if the launch is cwd-independent; otherwise they reject with `Working directory does not exist`.

### Temporary session cleanup

Catalog discovery opens an unprompted native session, reads its configuration, calls `session/close`, and removes that closed session's temporary artifacts while keeping a healthy shared control runtime alive (retiring and stopping the control process before cleanup if `session/close` fails or the launch is cwd-dependent). New sessions closed before their first prompt call `session/close` and remove their temporary artifacts: when the launch is cwd-independent and non-`full-access` (no `--dangerously-skip-permissions`), the session reached readiness and is idle (no active control/relaunch/interrupt work) with no configured MCP servers, and `session/close` succeeds on a healthy runtime, its idle process is detached and recycled into `StandbyRuntimePool` (if the slot for its launch/environment key is empty) while temporary artifacts are cleaned up; otherwise the dedicated ACP process is stopped before cleanup. Imported and prompted conversations are retained, and prompted processes are never recycled.

Only the closed session's validated UUID is eligible for deletion:

| Artifact under the native data directory      | Cleanup                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| `conversations/<id>.db`, `.db-wal`, `.db-shm` | Remove after `session/close` (and process stop for non-shared or failed runs) |
| `brain/<id>/`                                 | Remove that session's directory after `session/close` / process stop          |
| Shared summary databases and other sessions   | Retain                                                                        |

Cleanup refuses symlink targets and does not traverse symlink directories. Native close and filesystem cleanup are best-effort; errors do not discard an already-discovered catalog and may leave temporary artifacts.

## Models, modes, thinking and commands

Model, mode and thinking controls derive from native `configOptions`, enriched with Paseo mode visuals and an unattended **Full Access** (`full-access`) mode. Selecting `full-access` launches `agy acp` with `--dangerously-skip-permissions` (hot-reloading the session via `session/resume` when advertised or `session/load` otherwise when toggled on an open session), sets the native mode to `accept-edits` when advertised (falling back to `default`), and auto-approves remaining `'tool'`, `'mode'` and `'plan'` permission requests using `allow_once` (`'question'` prompts always require user selection); if a native `config_option_update` switches the mode to `'plan'`, `fullAccess` is cleared automatically, and switching back to another mode relaunches without `--dangerously-skip-permissions` and restores normal prompts. Preapproved MCP grants in `config.toolPolicy.preapproved` are also auto-approved with `allow_once` for both direct MCP tool names (`mcp__<server>__<tool>`, `<server>:<tool>`, and `default_api:mcp__<server>__<tool>`) and `call_mcp_tool` (`default_api:call_mcp_tool`) invocations. An explicit raw tool name overrides a descriptive permission title; supported legacy `Run ` title wrappers use the same identity resolver as timeline cards. Per-model thinking efforts derive from legacy `availableModels` suffixes against canonical effort levels (`low`, `medium`, `high`, `xhigh` / `Extra`, and `max`, including optional `-effort` suffixes, matched longest-first) merged with any additional choices advertised in `thought_level`; models with fixed or unadvertised efforts (such as `Orchestrator`) report `thinkingOptions: []`, and top-level session `thinkingOptions` remain empty whenever native `configOptions` omit `thought_level`. Session open and configuration apply `model -> thought_level -> mode` in order (preserving `availableModels` across relaunches): opening or switching to a fixed-effort model ignores a bundled `thinkingOption`, opening a new session also ignores an unsupported `thinkingOption` on effort-configurable models while strictly validating `model` and `mode`, restoring a persisted session additionally skips retired or unadvertised `model` and `mode` values to retain native state, switching to an effort-configurable model validates and applies `thought_level` after `model` exposes it, and standalone `thinkingOption` changes on a fixed-effort model reject before any relaunch. Opening a session changes configuration only when a requested value differs from native state. Effective configuration is published before `session.ready`. If opening fails after `session.opened` (including an early runtime exit, preserving `failureError`), `request.failed` is emitted before `session.closed`.

The provider waits up to one second for the current native session's initial `available_commands_update` before readiness so draft and live composers can query fresh commands, skipping this wait on persisted `session/load` opens for a valid UUID that replayed no history notifications (`user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`) and have neither local `<appData>/conversations/<id>.db` nor `<appData>/brain/<id>` artifacts (refusing symlinks). Command lists are not cached across sessions. An empty list also resolves the wait; close or failure releases it. If the deadline expires or the wait is skipped, readiness proceeds without an initial list. Changed command lists from later updates are forwarded; duplicate lists within a session are suppressed.

The connection negotiates these capabilities with Paseo and validates incoming operations against the negotiated set: `prompt.message`, `prompt.command`, `prompt.image`, `session.configure`, `session.list`, `session.persistence`, `session.can_stop_runtime`, `permission`, `permission.tool_policy`, and `session.subsession`.

## Attachments and tool cards

Dedicated cards require a known native tool identity or a trusted ACP kind hint; common argument keys alone do not classify an unknown MCP tool. Unknown cards retain JSON input and output separately, including nested null values. MCP identities share one resolver across live cards, permission grants and Brain replay: explicit raw `name` takes precedence over a title; otherwise only a complete supported identity (optionally wrapped in `Run ` / `default_api:`) is recognized. Native `mcp_<server>_<tool>` names are resolved against the session’s configured MCP server names only when exactly one server prefix matches. Overlapping prefixes require approval rather than a guessed split. `call_mcp_tool` resolves its server/tool from `ServerName` / `ToolName` (with the existing camelCase and lowercase aliases). Recognized calls display `server.tool`; input, case and call IDs are preserved. Display labels are never parsed back into permission keys. Descriptive titles, arbitrary dotted names, native `contrib:` names and ambiguous flattened names cannot grant access. Grants compare the resolved server and tool exactly, including case. Names containing extra `__` separators remain unnormalized and require approval unless supplied through the structured wrapper. The double-underscore and colon compatibility forms are adapter contracts, not verified current AGY spellings. AGY 1.5.8 binary inspection confirms the single-underscore native format, the default `Run ` title wrapper and PascalCase wrapper fields.

MCP output remains on the shared unknown JSON card. Dedicated MCP result-image extraction is not enabled without evidence that AGY supplies the image bytes and MIME type; input-image support does not prove result-image support. Tool terminal status follows ACP/Brain status, not a guessed interpretation of nested `isError`. MCP configuration forwarding and elicitation use the existing paths; this adapter adds no resource browser, server logos or MCP Apps framework. Note that `agy` itself enforces an approximately 1,500-byte description threshold for lazy-loading MCP tools, a 60-second HTTP response-header timeout, and a 180-second hard timeout on MCP tool execution; timeouts within those limits come from `agy` rather than this plugin.

The current connection uses ACP v1. Per the [tool-call raw-value contract](https://agentclientprotocol.com/protocol/v1/tool-calls), top-level `rawInput` / `rawOutput` null and omission both mean no supplied value on an initial call and leave the previous value unchanged on an update. Non-null values replace the corresponding channel, including `false`, `0`, `""`, `[]`, and `{}`. Content keeps its independent collection replacement behavior; when no raw output has been supplied, the unknown card preserves ACP content blocks. This ACP merge rule does not change nested JSON null or a directly recorded Brain result of null. Previously treating an ACP update's null as a clear instruction was incorrect.

Non-image attachments become text containing supplied paths, titles, external resource links (`title` + `url`), bodies or review comments. Uploaded files are referenced by daemon-side path; the plugin does not silently read arbitrary file contents. agy can use its own file tools subject to native permissions.

| Native arguments or content                                                             | Paseo card                                                                                                                       |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `CommandLine` / `command`                                                               | Shell command, working directory and output.                                                                                     |
| File path / native location                                                             | Read card with available output.                                                                                                 |
| `read_url_content` / `kind: 'fetch'` (`Url` / `url`)                                    | Fetch card with target URL and retrieved content.                                                                                |
| Write arguments (`ArtifactMetadata.RequestFeedback`: plan) or `exit_plan_mode` (`plan`) | Plan card when feedback is requested or `exit_plan_mode` supplies non-empty `plan` text, otherwise Write / structured tool card. |
| Edit/replace arguments or ACP diff                                                      | Edit card with old/new text or a diff.                                                                                           |
| Query / pattern                                                                         | Search card.                                                                                                                     |
| `invoke_subagent` / `send_message`                                                      | Subagent description, result and child link.                                                                                     |
| `ask_question`                                                                          | Plain-text formatted question options and answer.                                                                                |
| Unrecognized tool                                                                       | Structured `unknown.input` / `unknown.output`.                                                                                   |

Partial ACP tool updates are merged into full snapshots using stable item IDs. Denied tool permissions mark stranded tool cards `canceled` instead of `completed`; other running tools receive a completed, canceled or failed terminal snapshot before the turn ends. Missing failure detail gets a non-empty diagnostic.

## Persistence, history and subagents

Persistence stores the native session ID (`version: 1`). Replayed native history (`history: 'replay'`) uses `session/load` and arrives before `session.ready`. Skip-history loads (`history: 'skip'`) use `session/resume` when advertised in `sessionCapabilities.resume`, falling back to `session/load` while suppressing timeline rows and historical child discovery. Brand-new sessions require `cwd` to exist; reopening a persisted session whose original `cwd` was deleted falls back to the resolved `HOME` spawn directory for cwd-independent launches (preserving the original `cwd` on `session.opened` and `session/load` so history still replays), and synchronously rejects `session.prompt` with `Working directory does not exist`. Live echoed user chunks are suppressed because Paseo already received the user message with its client ID. The plugin drains queued ACP notifications before readiness and turn completion.

### Brain state and transcript projection

**Brain** is `agy`'s per-conversation local directory (`<appDataDir>/brain/<nativeSessionId>/`). Its `.system_generated/` subdirectory stores structured transcripts, inbox messages and subagent descriptors. **Reactive Wakeup** resumes model execution when a background task finishes, a timer fires, or a subagent sends a message after `session/prompt` has returned. ACP streams wakeup replies, thoughts, tool calls and permission requests as they occur. agy also writes the wakeup steps to Brain.

Child `conversationId` values are validated and translated to provider-scoped child IDs (`<sessionId>:child:<nativeChildId>`). The plugin reads `brain/<id>/.system_generated/logs/transcript_full.jsonl` (which preserves native JSON tool arguments, full untruncated text, and per-step token counters), retaining incomplete UTF-8 records between reads, along with structured state files under `brain/<id>/.system_generated/subagents/*.json` and `brain/<id>/.system_generated/messages/` (`*.json` and `read.json`). Realpath containment (including `lstat` checks rejecting symlink leaves and symlinked `appDataDir` roots) prevents reading or deleting outside Brain. Message identities use the native step index. Tool call IDs are correlated via `sourceMetadata.tool.toolCall.id` / `stepIndex` in `.system_generated/messages/*.json` and `spawnStepIndex` in `.system_generated/subagents/*.json`, with positional fallback within a prompt or history replay.

The plugin anchors each prompt to its new `USER_INPUT`. Once a foreground `PLANNER_RESPONSE` completes without pending tools or a `GENERIC` row registers background work, an actionable inbox `SYSTEM_MESSAGE` can enter the woken phase. Low-priority notices, pure `planexecute` handoffs and restart banners do not trigger it. The plugin matches ordered foreground ACP output against Brain to distinguish inbox work already streamed and charged inside the RPC from work after the response. Matching accepts agy's added paragraph break without changing the streamed text.

ACP supplies both foreground and wakeup replies, thoughts and tool starts. Brain still tracks tasks, subagents and inbox state, and can fill in tool results and child IDs. It does not publish a second text item or assign an anonymous fallback tool ID to a live ACP call. For an anonymous tool slot it checks the position and input in the full ACP turn, excluding invalid slots. If ACP is ahead of Brain, a verified foreground prefix can classify steps as already billed by the prompt RPC, but cannot assign a tool ID.

A `planexecute` notice is treated as pure only when `countRowMessages` is zero; this counter excludes user and low-priority headers and discounts the initial spawn message. A mixed notice with a counted `[Message]` header can therefore enter `'woken'` from `'foreground_idle'`. Headerless wakeups mixed with handoff notices are not distinguished by this rule.

Root turns use one incremental Brain reader from the start of the ACP prompt through final observation. During the initial foreground RPC it publishes only reliable model-context snapshots and completed checkpoints, retaining raw rows until ACP tool IDs, denials and elicitation updates have drained. Ordinary projection and settlement start after that handoff. The reader remains active while native elicitation is pending. Live context updates do not report turn consumption. A successful transcript read clears its preceding I/O fault; persistent read failures retain their latest diagnostic. Validation, projection and callback failures remain terminal because a partially applied fold cannot safely be replayed. Explicit cancel or close controls the terminal classification. Numeric-only usage changes do not open a new child turn, and unknown child capacity is omitted.

Cancellation is an ACP notification without a remote acknowledgement or Brain flush guarantee. The driver observes the outstanding prompt, local interruption work and queued ACP updates, then makes one serialized final read of complete records, including prefixes before a partial tail. Writes arriving beyond that boundary are not fabricated or polled indefinitely; restoration can recover them later. When `interrupt()` takes the fast path, it bounds `session/cancel` and active prompt convergence within `350 ms` and falls back to retiring and reloading the runtime asynchronously when reloadable (or failing and closing the runtime otherwise). Close invalidates the observation owner and shares a single terminal-event guard with prompt completion; it does not wait for a still-open transport before closing it. Native foreground context has phase-scoped priority; later known wakeup steps may update occupancy while retaining the observed same-model capacity.

ACP handles `ask_question` through `elicitation/create` during both prompts and wakeups. The stdio transport intercepts agy's multi-select schema because it omits the item `type` that the ACP SDK requires. The plugin shows a Paseo question permission and returns the selected options or custom text to agy. A pending question in Brain keeps the wakeup open while native elicitation and the follow-up reply arrive. Declining the question cancels the wakeup even if transcript I/O has not recovered; unrelated observation failures remain terminal.

Existing sessions can still be reopened. When reading older transcripts, a `USER_INPUT` immediately following an unlogged question is still treated as a continuation because the transcript does not distinguish the two.

When the ACP turn streamed model output and the session's Brain directory exists, the plugin waits up to 2 seconds for agy to flush the turn's `USER_INPUT` row; native commands that write no transcript row, and sessions without a Brain directory, complete immediately. A missing transcript follows the same bounded waiting policy when a known retry is unresolved; otherwise it completes the turn rather than failing it. Background tasks, subagents that have not settled (finished subagents stay `SUBAGENT_STATE_ALIVE` until killed) and pending approvals may keep a turn open indefinitely (interrupt stops them). Active woken-turn steps (pending tools and post-wakeup or post-tool model generation, including context compaction) wait up to 15 minutes per step (`wokenStallTimeoutMs`), while any other wait ends after 120 seconds (`stallTimeoutMs`) without transcript or inbox activity: when a stall timeout expires, the turn fails with an error item and interrupts the native session instead of hanging on an unrecognized final row.

Retry warnings are recognized only for the observed `ERROR_MESSAGE` / `DONE` system forms (after stripping a leading `Error: ` prefix): the exact stream-interruption notice, `API error (attempt N): ...` with a positive attempt number, the exact empty-model-output validation notice, and `Your previous response ...` or `There was a problem...` messages ending with `\nRetries remaining: N` for a positive remaining count. Unknown errors and explicit `ERROR` statuses still fail with their original message. Brain has no structured retry-exhaustion event, so a retry gets a bounded 15-minute silent window after its latest distinct warning step, matching the existing silent woken-model window. Timestamp-less warnings on an initial transcript read anchor to the file's `mtimeMs` (clamped to `Date.now()`), while live poll warnings anchor to `Date.now()`. Replaying that step (including across `O_TRUNC` rewrites) preserves its original `retryObservedAt` deadline unless a complete replacement snapshot (`snapshotStepIndices`) drops the step or mutates its warning message in place. Root settling, child watchers and runtime-work checks share this retry policy; the ordinary 120-second stall policy remains separate. Genuine later warnings refresh the window, and exhaustion preserves the latest underlying error. A completed model response, a new tool-bearing response or a correlated tool execution/result releases retry state; unrelated transcript rows do not. The root retry clock is not run while its foreground ACP prompt RPC is still in flight. The 15-minute value is a local resource policy, not proof of native exhaustion or a promise that silent generation can never exceed it. Tracked background processes, standing daemons and active descendants are not stopped merely because the model retry timed out; interruption still checks and stops their owner where required.

A `PLANNER_RESPONSE` with `status: DONE` can legitimately end without assistant text or tools. Completion uses its status and outstanding tools/messages/children, never the presence of prose. A trailing retry warning or an incomplete response still prevents completion; explicit cancellation remains authoritative. Brain does not expose a separate child turn-outcome marker, so an as-yet unwritten later error cannot be distinguished from a valid quiet ending by inspecting thinking text. If a new response supersedes tool calls that never logged a result, their visible cards are closed as canceled rather than falsely completed.

Subagent lifecycle is tracked directly from `.system_generated/subagents/*.json` (only `SUBAGENT_STATE_ALIVE` counts as active; `SUBAGENT_STATE_KILLED` cancels the watcher; other states are inactive) and `.system_generated/messages/read.json` across the session and its owned descendants. Nested subagents spawned by a child are linked under their direct parent subsession ID (`<root>:child:<childId>`).

- **Child failure.** An outstanding child's terminal failure fails the waiting turn rather than leaving it running, flushing terminal child states first and interrupting any remaining active sibling watchers or background work.
- **Re-wakeup correlation.** When a child spawned in an earlier turn is woken again via `send_message`, `server/brain-turns.ts` correlates `.system_generated/messages/*.json` (`sourceMetadata.tool.conversationId` and `sourceMetadata.tool.stepIndex`) and `stepIndex`-keyed completed wakeups against the parent's active turn boundary (`minStepIndex`, cached in `TurnBoundaryCache` under `${nodeId}:${beforeStep}` by `(mtimeMs, size, metaSignature)` covering `messages` and `subagents`, bounded to 256 entries) to advance the child's monotonic `TurnFloor` (`Math.max(turnFloor, turnStartStep)`, set to `startStep - 1` on re-wakeup) past prior-turn steps. Child settlement, retry deadlines and descendant tracking are all scoped above that floor, so historical child or grandchild failures from earlier turns do not poison later turns.
- **Tagged wakeups.** Tagged parent wakeups use this correlated floor even when multiple sends arrive in one parent turn: a later same-turn send cannot clear an earlier terminal failure.
- **Restart notices.** Only a header-anchored restart notice from the native `system` sender clears tracked background tasks and calls still awaiting a result; quoted notice text in child reports does not. A new `PLANNER_RESPONSE` also drops calls of the previous response that never logged a result, since child transcripts have no `USER_INPUT` to reset them.

| Transcript row     | Projection                                                                                                                                                                                                                                                                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USER_INPUT`       | User message.                                                                                                                                                                                                                                                                                                                                                     |
| `PLANNER_RESPONSE` | Thoughts, assistant text and initially running tool cards.                                                                                                                                                                                                                                                                                                        |
| `GENERIC`          | Match pending tool by `stepIndex` first, then first non-`ask_question` pending call, then FIFO. `RUNNING`/`WAITING` rows register background task IDs (`IsDaemon: true` schedules are tracked separately so idle turns settle); `manage_task` `kill` clears the killed task ID. `ERROR` fails, `CANCELED`/`INTERRUPTED` cancel, other terminal statuses complete. |
| `SYSTEM_MESSAGE`   | Anchor `sender=<id>` headers to match background task results, scheduled timer triggers and child notifications; ignore intra-turn `planexecute` handoff notices when classifying Reactive Wakeup while preserving subsequent wakeup responses.                                                                                                                   |
| `CHECKPOINT`       | Shift pending tool `stepIndex` references (`>= checkpoint` by `+1`). A `DONE` checkpoint emits a native completed compaction item with stable session/step identity and `preTokens` when `input_tokens + cache_read_tokens + (cache_write_tokens ?? 0)` is positive; other statuses emit no compaction item.                                                      |
| `ERROR_MESSAGE`    | Error item.                                                                                                                                                                                                                                                                                                                                                       |

Root history replay keeps all ACP snapshots and their relative order. Checkpoints are inserted only into gaps proved by verified tool call IDs or unique, complete, same-type text (`USER_INPUT` `<USER_REQUEST>` wrappers are normalized before comparison) that appears in consistent order in both sources, with local text/thought refinement inside already-bounded anchor gaps. Identity evidence belongs to each projected item: a pending tool records whether its ID came from that tool's native ID, its corresponding step metadata, or an aligned ACP tool snapshot with matching `rawInput` (skipping `GENERIC` `INVALID` calls and aligning forked transcript suffixes), and its trajectory step inherits that source (background task `GENERIC` `RUNNING`/`WAITING` rows anchor at their own `GENERIC` step, not the earlier `PLANNER_RESPONSE` or later `SYSTEM_MESSAGE` completion, preserving sibling tool order). An ID appearing on another tool cannot upgrade an unverified positional fallback into an anchor; generated-looking strings are not blacklisted when actually provided natively. Replay resolves metadata tool IDs using checkpoint-adjusted GENERIC steps before projecting the history. Unverified ordinal tool-ID fallback is neither a history anchor nor an identity for merging ACP results; unmatched Brain tools keep independent IDs. Sessions with and without checkpoints use the same result merge rules, retaining supplied ACP results and errors. Background completion messages retain verified identity for result recovery without becoming a second timeline anchor. Fragmented text, globally repeated text outside a bounded anchor gap, conflicting native IDs, missing anchors, or ACP-only items in a gap do not justify a position. Unlocated checkpoints produce one standard info notification per checkpoint per replay: history contains compaction, but its exact position is unknown. These notices omit a timestamp rather than imply that compaction happened at the end. Other independently proved gaps still retain native compaction markers and their original timestamps. This is a limitation of AGY's missing cross-source identity, not exact ordering parity with Codex.

ACP tool results and errors take precedence when provided. At the ACP v1 boundary, initial raw-output null/omission supplies no value; updates with null/omission retain the previous raw value regardless of status. Non-null values, including false, zero, empty strings, arrays and objects, are supplied results. A new full tool snapshot resets both raw-output and content presence. Content remains an independent collection: running empty arrays are placeholders, while explicitly supplied terminal empty arrays remain authoritative. Replacing running content with an empty array cannot leave an earlier content-present flag stuck on, and content updates never erase a supplied raw result. Nested JSON null and direct Brain JSON null remain data. When recovering missing results, supplied non-null ACP input takes precedence; if ACP supplied no input, the original Brain parameters and detail remain intact. Brain can also restore missing child ownership metadata without replacing an ACP terminal outcome or a supplied ACP result. Brain-only completed tools retain their existing recovery path.

Completed compaction items use the standard Paseo renderer in both Brain projection and history replay, preserving the native timestamp and populating `preTokens` from `CHECKPOINT` `input_tokens + cache_read_tokens + (cache_write_tokens ?? 0)` when positive (excluding `output_tokens` and omitting `trigger`). No loading state, manual/automatic trigger or post-compaction occupancy is inferred from checkpoint counters. Foreground root checkpoints are projected during existing post-RPC settling (including command-only transcripts); child watchers and Reactive Wakeup use their existing readers. Root RPC cancellation or failure currently skips settling, so checkpoints on those paths become visible on history replay rather than immediately. Live foreground observation and canceled/error final-drain parity are separate follow-up work.

agy appends each step once, when it reaches `RUNNING`, `WAITING` or `DONE` (or fails), and occasionally rewrites the whole file in place (`O_TRUNC`, same inode). The reader detects such rewrites by size, by re-checking the first bytes and the bytes before its offset, and when mid-`O_TRUNC` reads encounter corrupt partial lines, then resets to byte `0` and re-projects the file; `StepDedupe.fresh` hashes `(type, source, status, content, thinking, tool_calls, error)` with SHA-1 so a step is re-emitted only when its status or payload actually changed. For CHECKPOINT, only the first observed DONE per retained step identity emits completion; summary changes and later status regressions do not complete it again. A proven snapshot deletion or replacement by another event type releases that identity for reuse. Rows in `PENDING`, `QUEUED` or `GENERATING` can only come from a rewrite and are always superseded by a later row for the same step, so they are ignored.

A failed transcript read delivers no rows and rolls back its cursor, partial-byte remainder, file probes and pending snapshot indices together. Recovery therefore re-reads an unreturned complete prefix instead of reporting healthy after silently skipping it. Successful partial reads still deliver their complete rows immediately. An empty or torn rewrite observation does not delete delivered-step identities. Every complete JSONL record is immediately available to live, cancellation and history readers, even when the next record is partial. `reset` tells projectors to rebuild after a cursor reset; a separate `snapshotStepIndices` set authorizes dedupe pruning only after a nonempty replacement has no partial tail. The reader accumulates only step indices across partial reads, resetting that candidate set on another truncation or file replacement. Missing indices are then removed from the dedupe map and from `BrainNode`'s `retryObservedAt` map (`pruneRetrySteps`), and changed or subsequently reused indices remain visible. The map retains one digest per observed step, not transcript bodies or every historical revision; an empty file retains the preceding snapshot's identities. A new watcher/session owns a new map. AGY supplies no generation or rewrite-commit marker: clearing a file and restoring identical rows within the same watcher is indistinguishable from rewriting history and does not create new events. A newline-complete nonempty prefix is still treated as a replacement snapshot; a writer pausing between complete records cannot be distinguished from deletion without an upstream commit marker.

Native lifecycle tool matching reuses the ACP title normalizer: the outer `Run` wrapper is case-insensitive and accepts one or more whitespace characters, then `default_api:` is removed. The remaining lifecycle name must match exactly; foreign namespaces and extra suffixes are rejected. This is a parser contract, not a claim that agy emits every accepted wrapper variant.

Tool results do not become assistant bubbles. Child watchers emit `session.ready` immediately after `session.opened`, emit `session.turn(started)` lazily on their first active step, and emit completed or failed turn events when settled; successful native `manage_subagents` cancellation stops the affected watchers and emits canceled events. New native child turns restart lifecycle tracking. Cancellation (historical or live) first drains the child rows already written, so the child timeline is complete before its canceled turn, and finishes before the parent turn or session readiness is reported. Canceled children stay registered: they are never reopened and are closed with their parent. A later `send_message` to a child stopped by interruption resumes watching the same child session without replaying its history, after the previous watcher has drained; killed children are not resumed. Independent child control and Artifacts panels are unsupported.

## Permissions and runtime lifecycle

Permission events include the native title, input, detail card, classified `kind` (`question`, `mode`—including `switch_mode`, `exit_plan_mode` and `enter_plan_mode` with optional `contrib:` or title `Run ` prefixes when not overridden by a foreign MCP tool `name`—`plan`, or `tool`), and available actions. An action must match both the supplied ID and allow/deny intent (preferring `allow_once` / `reject_once` when no action ID is specified); no match cancels the request. A `deny` response marks the corresponding tool call ID as denied (converting live ACP `failed` updates and stranded tool cards to `canceled` without error, and settling `end_turn` immediately whether `agy` flushes the denied `GENERIC` `ERROR` row or leaves it unflushed until the next turn), and with `interrupt: true` also interrupts the active turn. Malformed fields, mismatched native session IDs, and requests during close or after runtime failure receive a canceled outcome before any approval is queued. Notifications are also checked against the current native ID, including buffered notifications flushed after opening. Interrupt, close and runtime failure resolve outstanding permissions as canceled. `clearPendingPermissions` does the same before handling a new prompt; it does not permit a second concurrent turn.

Interrupt stops active subagent watchers and checks within `200 ms` for running subagents or post-epoch background work, unread high-priority wakeups, active woken turns, or unresolved model retries (standing `IsDaemon: true` schedules are excluded so foreground interrupts do not kill them). When none are active (and no control relaunch/configure is in flight), interrupt sends `session/cancel` and awaits active prompt convergence within `350 ms` before falling back to retiring and recovering the runtime. When background work, active children, or cancel non-convergence requires retirement, the runtime drains subagent watchers up to `150 ms` (synchronously force-canceling remaining watchers if exceeded), sends a best-effort `100 ms` `session/cancel`, stops the ACP process and descendant process groups within Paseo's 2-second interrupt budget, and reloads the session asynchronously (preferring `session/resume` when advertised, otherwise `session/load`) with its model, thinking level, mode (`boolean(fullAccess)` rather than stale launch flags), and launch configuration preserved, because `session/cancel` can leave background tasks alive. During async recovery (`state.loading && state.ready`), incoming `config_option_update` notifications update internal metadata without publishing transient un-restored state until recovery finishes. Subsequent `session.configure` calls and new prompts serialize behind runtime recovery without blocking the interrupt response. A `RuntimeEpoch` boundary (`afterStepIndex`, `preEpochReadIds`, `ignoredMessages` reconciling post-epoch reads against post-epoch `[Message]` headers by signature, and `ignoredSubagentIds` unless touched post-epoch) is captured monotonically on runtime retirement (`replaceRuntime`), after `session/resume` or `session/load` completes (on interrupt recovery or `session.configure` mode/`full-access` relaunch), and when reopening a persisted session (`history: 'replay'` reuses `replayTools()` reads and cancels stranded mid-turn historical child watchers), ignoring pre-stop tasks, daemons, children and stale inbox state later. Conversation history is retained; an unexpected prompt failure falls back cleanly, and a reload failure fails queued configuration and turns with the underlying diagnostic until the session is reopened.

Control RPCs time out after 30 seconds. Prompt generation remains open until completion, interruption or process failure. On Unix, shutdown snapshots the ACP process's descendant process groups within a `200 ms` `ps` discovery budget (`killSignal: 'SIGKILL'` on timeout, BusyBox fallback within budget, latched on failure so broken `ps` is not invoked twice; if `child` exits while discovery is still running, up to `50 ms` is allowed for stdout flush) before closing `stdin`, waits up to `300 ms` for graceful exit on EOF, then refreshes the snapshot and sends `SIGKILL` to tracked descendant process groups, followed by `SIGKILL` to the direct child at `650 ms` and a hard termination deadline at `1,100 ms` (rejecting `close()` and failing the session if exceeded). Where `ps` is unavailable, shutdown still terminates agy's own process group and never fails because of it. Explicit close (including a close arriving while `session.open` is still in flight) stops Brain polling and terminates the session's ACP process while preserving imported and prompted conversations (unless `config.persist === false`, which removes temporary artifacts on close). Paseo's idle runtime check (`session.can_stop_runtime`) returns `false` while `closing`, `opening`, `loading`, `controlActive > 0`, `turn`, or `interrupting` is active, returns `true` once `failed`, returns `false` while `permissions` are pending or `subagents.hasRunningChildren()` (including active watcher resumptions) is true, and otherwise checks `hasActiveBackgroundWork` with `includeDaemons: true` across post-epoch background tasks, standing `IsDaemon` schedules, post-epoch unread/unprocessed high-priority inbox messages, active woken turns, unresolved model retries within 15 minutes, post-epoch or post-epoch-touched `SUBAGENT_STATE_ALIVE` children/descendants, and Brain read errors.

Protocol disconnection drains `stderr` and exit status before closing the readable stream, then terminates the child even if the process is still alive. Provider connection shutdown awaits all in-flight operations, terminates all active transports, and waits for shutdown to finish.

Steering, rewind, archive operations and structured output are unsupported.

## Context window occupancy

Paseo's context meter needs both `contextWindowUsedTokens` and a positive `contextWindowMaxTokens`. On live `usage_update` notifications, turn settlement, model switches, and persisted session restoration, the plugin reads the effective server-issued auto-compaction window from `<appData>/conversations/<nativeId>.db` (read-only with a `50 ms` busy timeout, single snapshot-atomic scan of `gen_metadata` `ChatStartMetadata.context_window_metadata.context_window_usage.max_context_tokens` strictly by `idx DESC`) using a monotonic SQLite row cursor (`genIdx`) so a prior model's metadata cannot be misattributed after a model switch, caches it per model in the session, and applies it immediately—including during Turn 1 streaming and live model switches—falling back to native `usage_update.size` (`MaxInputTokens`) only when no SQLite compaction window has been observed yet for the active model. Valid native `usage_update` notifications take precedence for occupancy during the foreground phase; later Reactive Wakeup planner snapshots can update occupancy while retaining the same model's known capacity; used tokens must be finite and nonnegative. When neither `usage_update.size` nor a SQLite compaction window has been observed for the active model, `contextWindowMaxTokens` is omitted rather than guessed. Only USD costs populate `totalCostUsd`.

agy prompt responses report cumulative token counters across internal model steps (including multi-model `Orchestrator` / `planexecute` handoffs between the Carbon/Argon planner and Hydrogen executor on a single trajectory), whereas `transcript_full.jsonl` records exact per-step `input_tokens`, `cache_read_tokens` and `output_tokens` on each `PLANNER_RESPONSE` (capturing KV-cache hits and cross-model cache misses per step). When no valid foreground `usage_update` arrives, or later Reactive Wakeup steps execute, the plugin computes context window occupancy from the latest reliable `PLANNER_RESPONSE` usage snapshot in `transcript_full.jsonl`:

```text
usedTokens = lastStep.inputTokens + lastStep.cachedReadTokens + lastStep.cachedWriteTokens + lastStep.outputTokens
```

`cachedWriteTokens` is taken from the step's `cache_write_tokens` when agy records it and is otherwise zero. Per-step and cumulative ACP counters are never mixed for occupancy. The plugin adds post-RPC wakeup consumption to the turn that produced it. agy consumes those streamed steps immediately, so the next prompt reports independent usage.

When no reliable step-level counters are available, context occupancy falls back to the latest SQLite `gen_metadata` `estimated_tokens_used` when present (never overriding `usage_update.used` or `transcript_full.jsonl` step counts), and otherwise stays unchanged or unknown; cumulative ACP prompt counters never substitute for context occupancy. Cancellation and prompt errors recover only snapshots after the current turn boundary. Restoration can recover the latest historical snapshot when native context is absent, pairing it with the persisted model's SQLite compaction window or `usage_update.size` when available. Cache-only model steps with positive usage are valid snapshots; invalid and all-zero placeholder counters (both transcript step usage and ACP prompt `result.usage`) are ignored. A native `usage_update` explicitly reporting zero remains valid. Snapshot-only updates never replace turn consumption. Restoration publishes context after applying requested model configuration, and clears prior-model capacities when switching to a model with no observed window.

Snapshot recovery reads complete records backwards in 64 KiB blocks, stops at this turn's boundary, and retains at most one JSONL record (8 MiB limit). If no snapshot exists, a historical restore can still scan the full file; it does not retain the full transcript. Cancel/error recovery also records the highest observed complete step so a later turn cannot claim canceled history as its own.

For snapshot recovery and turn boundaries, a complete JSON record at the observed file end is readable even without a final newline; an unparseable partial record is skipped. This restores the existing tail-index behavior, but does not establish that the writer has finished or prevent later revisions. The streaming transcript reader still requires a newline to deliver a record; this tail-only measurement never authorizes replacement-snapshot pruning.

At turn completion or cancellation/error recovery, one shared final tail measurement reconciles complete EOF records even when live observation already cached usage. Older or absent snapshots retain observed context; a newer complete step without usage still advances the turn boundary. This does not add consumption or override authoritative foreground native context. An already closed session skips this recovery and cannot publish late updates.

Transcript rewrites reconstruct the current Paseo turn from its first user input, replaying foreground and Reactive Wakeup phases in order. Anonymous tools process task registration and completion immediately while their timeline emissions wait for an identity. Confirmed removal invalidates the internal usage source cache without publishing zero context or discarding the last known display value.

ACP `session/cancel` is a notification, not a server acknowledgement. Recovery waits for local interruption/relaunch work and drains pending ACP notifications after the original prompt resolves or rejects, then reads the complete records currently available. A runtime that writes Brain after those observable boundaries cannot be guaranteed to have flushed: no sleep or invented acknowledgement is used. Later history restoration can recover late counters without charging them to a new turn.

Prompt token counters are merged with context usage and emitted before turn completion. Context occupancy and subscription quota are separate measurements.

## Subscription quota

Usage Source `agy` supplies the Composer context popover and `paseo usage ls --json`. Add `--refresh` to bypass the host's cached report.

### Account discovery

Global discovery considers observed account directories (bounded to 100 entries) and the default data directory. Session discovery serves provider IDs `agy` and `antigravity`, resolving the directory using the session environment and a matching remembered launch. Paseo's usage scope has no launch command; if several custom launches match the same environment, the latest observation wins.

Account keys are SHA-256 hashes of data directories. A non-empty `antigravity-oauth-token` file, a login line in the retained logs, or a remembered launch makes a directory discoverable. agy 1.5 and later keeps credentials in the OS keychain and writes no token file, so the login line and the remembered launch are the signals that survive there; a directory with none of them is skipped. Labels use the latest login match across `cli.log` (always retained) plus up to ten most recent `log/cli-*.log` and `log/acp-server-*.log` files, contained within the resolved data directory and deduplicated by `realpath`. Each file checks the last 64 KiB first (so mid-session sign-ins take precedence) and, for larger files, the first 64 KiB (so startup auth lines survive long sessions). Missing logs fall back to `Antigravity`. Token contents are not read or copied into usage inputs.

Successful catalog discovery and session opening remember `_meta.antigravity.tier.name` as `planLabel`. The label is absent until observed and can be stale after an account change.

### Query execution

Fetching runs the launch executable with `-p /usage --output-format json` and a 15-second timeout. The `acp` subcommand and transport flags are removed; explicit directory arguments, the remembered working directory and launch/session environment overrides are preserved. Non-default account directories without a remembered launch or active session discovery context return an error instead of querying the default account, and interactive CLI sign-in prompts are aborted immediately as authentication errors. If the remembered workspace no longer exists, execution falls back to the host home directory only when the resolved account directory stays identical and the executable is not a relative path. Cwd-dependent directory flags produce a diagnostic instead of silently switching accounts. Other launch arguments remain unchanged. No directory flags are added for default accounts. Current agy print mode rejects ACP directory flags, so such launches return a command error instead of querying a different account.

The CLI may contact its quota service but does not start a model turn. The plugin does not modify login credentials.

### Windows and outcomes

Each validated `command.data.groups` bucket becomes a scoped window (non-`SUCCESS` top-level statuses surface as errors; explicitly `disabled: true` buckets and unidentifiable non-standard buckets lacking both `id` and `window` are skipped without failing sibling buckets):

| Native field         | Reported behavior                                                                  |
| -------------------- | ---------------------------------------------------------------------------------- |
| Group name           | Scope label and normalized ID, such as `gemini_models` or `claude_and_gpt_models`. |
| `window: 5h`         | Five-hour window (18,000 seconds).                                                 |
| `window: weekly`     | Weekly window (604,800 seconds).                                                   |
| Unknown window       | Preserve native window identity and labels without inventing a duration.           |
| `remaining_fraction` | Convert to a rounded, clamped used percentage; absent fractions stay unknown.      |
| `reset_time`         | Trimmed reset timestamp, or no timestamp when absent or whitespace-only.           |

Windows are included in the default summary. Usage above 90% has a danger tone; 70–90% has a warning tone; lower known usage is OK and unknown usage uses the default tone.

| Outcome                                             | Usage report                                                      |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| Valid quota buckets                                 | `available`, with windows and the observed plan label when known. |
| No buckets                                          | `unavailable` with `no_quota`.                                    |
| Command, authentication, timeout or parsing failure | `error` with a diagnostic.                                        |
| No token file, login line or remembered launch      | Omit the account from discovery.                                  |
| Non-default account without launch context          | `error` instead of querying the default account.                  |
| Login store removed but the CLI still answers       | Report the CLI result; the token file is not authoritative.       |
